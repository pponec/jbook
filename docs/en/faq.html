Frequently Asked Questions (FAQ)

  • Do I need any prior IT knowledge?
    Not at all. The book is written for complete beginners. We start from scratch: we'll explain what memory is, how bits work, and gradually move on to programming. If you can install a standard computer game, you can install Java.
  • What do I need to install?
    You will only need Java 25 LTS. The acronym LTS (Long Term Support) means it is a stable version with long-term support that you can rely on.
  • Will it run on my computer?
    Yes. Java is universal, so the examples work on Windows, macOS, and Linux. You don't even need a high-performance machine – if you use Linux (e.g., Xubuntu), 2 GB of RAM is enough.
  • What's new in the 3rd edition?
    The third edition goes deeper and broader. I have added:
    • An introduction to relational databases (SQL).
    • Working with memory.
    • A demonstration of using Artificial Intelligence (AI) in game strategy design.
    • Basics of versioning in Git (a must for every programmer).
    • All original chapters have undergone a thorough new revision to improve readability and understanding.
  • What technologies will the book teach me?
    We will create real web applications. All examples are part of a single Maven project running on the lightweight Jetty web server. We will learn to create HTML code purely using Java objects (using the Element class), which helps you understand OOP principles better than just writing text templates. Curious readers can look at the source code now.
  • Why teach Servlets instead of the Spring framework?
    Because Servlets are the alphabet of the web. Modern frameworks (like Spring Boot) are just wrappers that hide a lot. Whoever learns Servlets will understand how the web actually works "under the hood." The transition to complex frameworks will then be much easier for you.
  • HTML as objects? Isn't it better to write HTML code directly?
    For teaching programming, the object-oriented approach is better. When we build a page using objects (Java classes), we learn to think like a programmer, not just a web coder. It forces you to understand the page structure (tree) and the relationships between elements.
  • Won't working with the Element class be complicated?
    On the contrary, it's like a building set. We only need three methods:
    1) addElement(...) – adds a new block (element),
    2) setAttribute(...) – sets its properties,
    3) addText(...) – writes text inside.
    You don't need more to start with.
  • Is this method memory-efficient?
    Yes, very much so. The Element class works like a flow heater – data doesn't accumulate in it but is sent directly to the output (the browser). Thanks to this, we can generate even huge pages without the risk of running out of memory.
  • Why don't we use JSP or JSF?
    Because the goal is to teach you Java and object-oriented thinking, not to overwhelm you with the syntax of templating languages, which often provoke mixed reactions in the community. We will stick to clean code.
  • Will I really understand it, or just "copy the code"?
    The book is written against the principles of cargo cult programming. I don't want you to blindly copy commands. The book explains why things happen and what the connections are. At the same time, I don't want to overwhelm you with details that you don't need at the beginning, so you don't lose motivation.
  • Isn't it too many technologies for a beginner?
    It might seem so (HTML, CSS, Maven, Java), but there's no reason to worry. Tools like Maven are used only as "background assistants"; we won't learn them in depth. We focus on Java. HTML and CSS are kept to a necessary minimum. Everything is prepared so that we can start creating together right after installing Java.
  • What is Ujorm?
    Ujorm was, in its time, a unique ORM framework for modeling type-safe database queries. Today, only certain modules for general use are actively maintained, such as the support for generating HTML pages using an object model.
